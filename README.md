# موقع المصوّر — دليل التشغيل الكامل

موقع معرض أعمال احترافي لمصوّر مع لوحة تحكم خاصة. بعد التشغيل يدير المصوّر كل شيء بنفسه من الهاتف أو الكمبيوتر — الصور والألبومات والخدمات والباقات والأسعار والنصوص ومعلومات التواصل والحجوزات — بدون أي تعديل على الكود.

**التقنيات:** Next.js (App Router) · TypeScript · Tailwind CSS · Supabase (قاعدة بيانات PostgreSQL + تسجيل الدخول + تخزين الصور).

## 1. البرامج المطلوبة

| البرنامج | لماذا | الرابط |
|---|---|---|
| Node.js 20.9 أو أحدث (يفضّل 22) | لتشغيل وبناء الموقع | https://nodejs.org |
| حساب Supabase (مجاني للبداية) | قاعدة البيانات وتخزين الصور وتسجيل الدخول | https://supabase.com |
| حساب Vercel (مجاني للبداية) | نشر الموقع على الإنترنت | https://vercel.com |
| حساب GitHub (مستحسن) | لحفظ الكود وربطه بـ Vercel | https://github.com |
| محرر نصوص مثل VS Code (اختياري) | لفتح الملفات | https://code.visualstudio.com |

## 2. تثبيت Node.js

1. ادخل https://nodejs.org ونزّل نسخة **LTS**.
2. ثبّتها بالضغط على «التالي» حتى النهاية.
3. افتح «الطرفية» (Terminal على Mac، أو PowerShell على Windows) واكتب:
   ```bash
   node -v
   ```
   يجب أن يظهر رقم مثل `v22.x.x`.

## 3. تثبيت المكتبات

افتح الطرفية داخل مجلد المشروع (`studio-portfolio`) ثم:

```bash
npm install
```

ينتظر دقيقة أو اثنتين حتى ينتهي.

## 4. إنشاء مشروع Supabase

1. ادخل https://supabase.com/dashboard واضغط **New project**.
2. اختر اسمًا (مثلًا `studio`) وكلمة مرور قوية لقاعدة البيانات **واحفظها**.
3. اختر أقرب منطقة لجمهورك (مثلًا Frankfurt لعملاء العراق والخليج).
4. انتظر حتى يجهز المشروع (دقيقتان تقريبًا).

### إيقاف التسجيل العام (مهم)

لا يجب أن يستطيع أي زائر إنشاء حساب:

**Authentication ← Sign In / Providers ← Email** وأوقف **Allow new users to sign up**.

> حتى لو بقي التسجيل مفعّلًا بالخطأ، أي حساب جديد **لا يملك أي صلاحية** — الصلاحية تأتي فقط من جدول `admin_users`. لكن إيقافه أنظف.

## 5. تنفيذ ملفات قاعدة البيانات

في لوحة Supabase افتح **SQL Editor ← New query** ثم انسخ محتوى كل ملف والصقه واضغط **Run**، **بهذا الترتيب**:

1. `supabase/migrations/20261004000100_schema.sql` — الجداول والفهارس.
2. `supabase/migrations/20261004000200_security.sql` — الصلاحيات وقواعد الأمان.
3. `supabase/migrations/20261004000300_storage.sql` — مساحة الصور وقواعدها.
4. (اختياري) `supabase/seed.sql` — تصنيفات وخدمات مبدئية يمكنك تعديلها أو حذفها لاحقًا.

يجب أن تظهر رسالة `Success` بعد كل ملف. **هذه الملفات آمنة لإعادة التشغيل** — تنفيذها مرة ثانية لا يكرر شيئًا ولا يحذف بياناتك.

> **للمطورين:** يمكن أيضًا استخدام Supabase CLI: `npx supabase link` ثم `npx supabase db push`.

## 6. مساحة تخزين الصور (Storage)

الملف الثالث أعلاه ينشئ مساحة باسم `media` تلقائيًا. للتأكد: **Storage** في القائمة الجانبية — يجب أن تجد `media` ومكتوب بجانبها **Public**.

- الحد الأقصى لحجم الصورة: **15 ميغابايت**، والأنواع المسموحة: JPG وPNG وWebP وAVIF.
- لتغيير الحد: عدّله في `lib/config/media.ts` **وفي** ملف `..._storage.sql` ثم أعد تنفيذ ملف التخزين.

إذا لم تظهر المساحة لأي سبب، أنشئها يدويًا: **New bucket** ← الاسم `media` ← فعّل **Public bucket** ← حدد الحجم 15MB والأنواع `image/jpeg, image/png, image/webp, image/avif`، ثم نفّذ ملف التخزين مرة أخرى لإضافة القواعد.

## 7. قواعد الأمان (RLS)

تُطبّق تلقائيًا من الملفين الثاني والثالث. للتأكد: **Database ← Tables** — يجب أن يظهر بجانب كل جدول **RLS enabled**.

ملخص القواعد:

| | الزائر | مستخدم مسجّل ليس مديرًا | المدير |
|---|---|---|---|
| قراءة الإعدادات والتصنيفات | ✓ | ✓ | ✓ |
| قراءة الصور والألبومات والخدمات والباقات | المنشور فقط | المنشور فقط | الكل |
| تعديل أو حذف أي محتوى | ✗ | ✗ | ✓ |
| قراءة الحجوزات وملاحظاتها الداخلية | ✗ | ✗ | ✓ |
| إنشاء حجز | عبر نموذج الحجز فقط (من الخادم) | نفس الشيء | ✓ |
| رفع/حذف الصور في التخزين | ✗ | ✗ | ✓ |

## 8. متغيرات البيئة

1. انسخ الملف `.env.example` إلى ملف جديد باسم `.env.local`:
   ```bash
   cp .env.example .env.local
   ```
2. من Supabase: **Project Settings ← API Keys** (أو **Data API** للرابط) واملأ:

| المتغير | من أين | سري؟ |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | لا |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key (`sb_publishable_...`)، أو anon key في المشاريع القديمة | لا |
| `NEXT_PUBLIC_SITE_URL` | رابط موقعك النهائي، مثل `https://www.studio.com` (محليًا: `http://localhost:3000`) | لا |
| `SUPABASE_SECRET_KEY` | Secret key (`sb_secret_...`)، أو service_role key في المشاريع القديمة | **نعم** |
| `BOOKING_HASH_SALT` | نص عشوائي طويل — أنشئه بالأمر أدناه | **نعم** |
| `BOOKING_MAX_PER_HOUR` | اختياري: أقصى عدد طلبات حجز من نفس الزائر في الساعة (الافتراضي 5) | لا |

لإنشاء نص عشوائي:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> ⚠️ **لا تضع `NEXT_PUBLIC_` قبل أي مفتاح سري.** كل ما يبدأ بـ `NEXT_PUBLIC_` يصل إلى متصفح الزائر. المفتاح السري يستخدم على الخادم فقط لحفظ طلبات الحجز ولإنشاء المدير الأول.
>
> ملف `.env.local` موجود في `.gitignore` فلن يُرفع إلى GitHub.

## 9. إنشاء أول مدير

**الطريقة الأسهل (من الطرفية):**

```bash
npm run create-admin -- you@example.com "كلمة-مرور-قوية-12-حرفًا-على-الأقل"
```

أو بدون كتابة البيانات في الأمر (سيسألك عنها):

```bash
npm run create-admin
```

**الطريقة البديلة (من لوحة Supabase):**

1. **Authentication ← Users ← Add user ← Create new user**: اكتب البريد وكلمة المرور وفعّل **Auto Confirm User**.
2. **SQL Editor** ونفّذ (بعد تغيير البريد):
   ```sql
   insert into public.admin_users (user_id, role)
   select id, 'owner' from auth.users where email = 'you@example.com'
   on conflict (user_id) do update set role = 'owner';
   ```

**إضافة مدير ثانٍ لاحقًا:** نفس الخطوات بدور `'admin'`. **سحب الصلاحية:** `delete from public.admin_users where user_id = '...';`

## 12. النشر على الإنترنت (Vercel)

الموقع يحتاج خادمًا (تسجيل الدخول، الحجوزات، تحديث المحتوى فورًا) لذلك **لا يستخدم Static Export**. Vercel هو الخيار الأبسط لـ Next.js.

1. ارفع المشروع إلى مستودع **خاص** على GitHub:
   ```bash
   git init
   git add .
   git commit -m "first version"
   git branch -M main
   git remote add origin https://github.com/USERNAME/studio-portfolio.git
   git push -u origin main
   ```
2. في https://vercel.com/new اختر المستودع واضغط **Import**.
3. قبل **Deploy** افتح **Environment Variables** وأضف نفس متغيرات `.env.local` (مع تغيير `NEXT_PUBLIC_SITE_URL` إلى رابط موقعك).
4. اضغط **Deploy** وانتظر.
5. في Supabase: **Authentication ← URL Configuration** ضع **Site URL** = رابط موقعك.

بعد النشر جرّب: تسجيل الدخول، رفع صورة، إرسال حجز تجريبي، تعديل الإعدادات.

> تعديلات المصوّر تظهر فورًا بدون إعادة نشر: كل حفظ في لوحة التحكم يحدّث نسخة الموقع المخزنة.

**بدائل:** أي منصة تدعم Next.js بالخادم (Netlify، Railway، Render، أو خادم VPS بـ `npm run build && npm start`).

## 13. ربط النطاق (الدومين)

1. Vercel ← المشروع ← **Settings ← Domains** ← أضف نطاقك (مثل `studio.com` و`www.studio.com`).
2. Vercel يعطيك سجلات DNS؛ أضفها عند الجهة التي اشتريت منها النطاق:
   - `A` للنطاق الرئيسي ← العنوان الذي يعرضه Vercel.
   - `CNAME` لـ `www` ← `cname.vercel-dns.com`.
3. انتظر من دقائق إلى ساعات حتى يعمل. شهادة HTTPS تُضاف تلقائيًا.
4. حدّث `NEXT_PUBLIC_SITE_URL` في Vercel إلى النطاق الجديد ثم **Redeploy**، وحدّث **Site URL** في Supabase.

## 14. النسخ الاحتياطي

- **قاعدة البيانات:** الخطط المدفوعة في Supabase تأخذ نسخًا يومية تلقائية (**Database ← Backups**). نسخة يدوية في أي وقت:
  ```bash
  npx supabase db dump --db-url "postgresql://postgres:[PASSWORD]@db.[REF].supabase.co:5432/postgres" -f backup.sql --data-only
  ```
  (رابط الاتصال من **Project Settings ← Database ← Connection string**).
- **الصور:** من **Storage ← media** يمكن تنزيل المجلدات، أو للمطورين: `npx supabase storage cp -r ss:///media ./media-backup --experimental`.
- **الكود:** محفوظ في GitHub.

ينصح بنسخة يدوية شهرية للبيانات والصور على قرص خارجي.

## دليل المصوّر: استخدام لوحة التحكم

ادخل `/admin` من الهاتف أو الكمبيوتر. على الهاتف: الأقسام الأكثر استخدامًا في الشريط السفلي، والباقي من زر القائمة أعلى الشاشة.

| أريد أن… | اذهب إلى |
|---|---|
| أرفع صورًا (واحدة أو عدة صور معًا) | **الصور ← إضافة صور** (أو اسحب الصور إلى المربع) |
| أختار صور الصفحة الرئيسية | افتح أي صورة ← فعّل «تظهر في الأعمال المختارة» — أو حدد عدة صور ← «تمييز» |
| أحذف صورة | افتح الصورة ← حذف الصورة (أو «اختيار» لعدة صور) |
| أغير ترتيب الصور | **الصور ← ترتيب الصور** واستخدم الأسهم |
| أنشئ ألبومًا | **الألبومات ← إضافة ألبوم** ← احفظ ← ثم «إضافة صور من المكتبة» أو «رفع صور جديدة للألبوم» |
| أختار غلاف الألبوم | داخل الألبوم: زر النجمة على الصورة |
| أنشر أو أخفي ألبومًا | داخل الألبوم: مفتاح «الحالة: منشور/مسودة» |
| أضيف تصنيفًا (أعراس، تخرج…) | **التصنيفات ← إضافة تصنيف** |
| أضيف خدمة | **الخدمات ← إضافة خدمة** |
| أضيف باقة أو أغير سعرها | **الباقات ← إضافة باقة** أو افتح الباقة |
| أخفي باقة بدون حذفها | **الباقات** ← مفتاح «ظاهر/مخفي» |
| أتابع الحجوزات | **الحجوزات** ← افتح الحجز ← اتصال / واتساب / غيّر الحالة / ملاحظات داخلية |
| أغير الشعار أو صورة الغلاف أو النصوص | **إعدادات الموقع ← عام** و**نصوص الصفحات** |
| أغير الهاتف أو واتساب أو العنوان | **إعدادات الموقع ← التواصل** |
| أضيف إنستغرام/فيسبوك/تيك توك | **إعدادات الموقع ← التواصل الاجتماعي** (الحقل الفارغ لا يظهر في الموقع) |
| أغير الألوان | **إعدادات الموقع ← المظهر** |

**ملاحظات مهمة:**
- رقم واتساب يُكتب بالصيغة الدولية بدون صفر وبدون +، مثل `9647701234567`.
- لفتح واتساب العملاء الذين كتبوا رقمًا محليًا (مثل 0770…) أضف «رمز الدولة» (مثل `964`) في التواصل.
- خيار «تصغير الصور الكبيرة جدًا» عند الرفع يحافظ على جودة عالية (حتى 3200 بكسل) ويجعل الموقع أسرع. أوقفه إذا أردت رفع الملف الأصلي كما هو.
- صور iPhone بصيغة HEIC: الهاتف يحولها تلقائيًا إلى JPG عند الرفع من المتصفح غالبًا. إن ظهرت رسالة «نوع الملف غير مدعوم» اختر في إعدادات الكاميرا ← Formats ← **Most Compatible**.

## بنية المشروع

```
app/
  (site)/                 الموقع العام (الرئيسية، الأعمال، الألبوم، الباقات، الحجز، من نحن، تواصل)
  admin/login/            صفحة دخول المدير
  admin/(panel)/          لوحة التحكم (محمية) — الرئيسية، الصور، الألبومات، التصنيفات، الخدمات، الباقات، الحجوزات، الإعدادات
  layout.tsx              الهيكل الأساسي (RTL، الخطوط، الألوان، بيانات SEO)
  sitemap.ts, robots.ts   خريطة الموقع وملف robots
components/
  site/                   مكونات الموقع العام (الهيدر، المعرض، Lightbox، بطاقات الباقات…)
  admin/                  مكونات لوحة التحكم (رفع الصور، النماذج، الحوارات، الإشعارات…)
  forms/                  نموذج الحجز
  ui/                     مكونات مشتركة (عرض الصور المحسّن)
lib/
  actions/                عمليات الخادم (Server Actions) — كل عملية تتحقق من صلاحية المدير
  data/                   قراءة البيانات (عامة ومخصصة للمدير)
  validation/             قواعد التحقق من المدخلات (zod)
  supabase/               اتصالات Supabase (متصفح، خادم، عام، سري للخادم فقط)
  upload/                 تجهيز الصور ورفعها من المتصفح مع نسبة التقدم
  i18n/                   نصوص الواجهة (العربية) — جاهزة لإضافة لغة أخرى
  config/media.ts         حدود رفع الصور
  utils/                  أدوات مساعدة (السعر، التاريخ، واتساب، الروابط…)
types/content.ts          أنواع البيانات
supabase/
  migrations/             ملفات قاعدة البيانات (الجداول، الأمان، التخزين)
  seed.sql                بيانات مبدئية اختيارية
  tests/                  اختبارات قاعدة البيانات والأمان (محليًا فقط)
scripts/                  إنشاء المدير الأول، فحص ملفات المتصفح
proxy.ts                  يحوّل غير المسجلين من /admin إلى صفحة الدخول ويجدد الجلسة
```

## قاعدة البيانات

| الجدول | المحتوى |
|---|---|
| `admin_users` | من يملك صلاحية الإدارة (`owner` / `admin` / `editor` محجوز للمستقبل) |
| `site_settings` | صف واحد: كل نصوص الموقع ومعلومات التواصل والروابط وSEO والمظهر |
| `categories` | التصنيفات |
| `media` | الصور (المسار، الأبعاد، الوصف، التصنيف، مميزة، ظاهرة، الترتيب) |
| `albums` | الألبومات (العنوان، الرابط الفريد، الغلاف، الحالة…) |
| `album_media` | ربط الصور بالألبومات مع الترتيب (صورة واحدة يمكن أن تكون في عدة ألبومات) |
| `services` | الخدمات |
| `packages` | الباقات (السعر، العملة كنص حر، قائمة ما تتضمنه بصيغة JSONB) |
| `bookings` | طلبات الحجز (مع نسخة من اسم الخدمة/الباقة وسعرها وقت الحجز) |

**سلوك الحذف المقصود:**
- حذف تصنيف ← الصور والألبومات تبقى بدون تصنيف.
- حذف صورة ← تُزال من الألبومات، وإن كانت غلافًا يصبح الغلاف أول صورة في الألبوم.
- حذف ألبوم ← صوره تبقى في المكتبة.
- حذف خدمة أو باقة ← الحجوزات السابقة تحتفظ باسمها وسعرها.

**دوال قاعدة البيانات:** `is_admin()`، `reorder_items()`، `set_album_media()`، `add_media_to_album()`، `submit_booking()` (الوحيدة التي تنشئ حجزًا: تتحقق من التاريخ، تمنع التكرار خلال 10 دقائق، وتحد من عدد الطلبات لكل زائر).

## الأمان

- **RLS مفعّل على كل الجداول** وعلى التخزين، ومختبر بـ 70 اختبارًا (`npm run test:db`).
- **صلاحية المدير لا تعتمد على مجرد تسجيل الدخول:** يجب وجود المستخدم في `admin_users`.
- **حماية لوحة التحكم على ثلاث طبقات:** `proxy.ts` (تحويل غير المسجلين) ← تخطيط اللوحة يتحقق من الصلاحية على الخادم ← كل عملية حفظ تتحقق مرة أخرى، وقاعدة البيانات نفسها ترفض أي تعديل من غير المدير.
- **نموذج الحجز:** تحقق على المتصفح وعلى الخادم، تنظيف المدخلات، حقل مخفي لاصطياد البرامج الآلية (honeypot)، رفض الإرسال الأسرع من 2.5 ثانية، منع الضغط المزدوج، وحد أقصى للطلبات من نفس الزائر (عنوانه يُحفظ مشفّرًا فقط). إذا زاد السبام يمكن إضافة Cloudflare Turnstile في `components/forms/BookingForm.tsx` و`lib/actions/booking.ts`.
- **الرفع:** فحص نوع الملف الحقيقي من محتواه (وليس الامتداد)، حد للحجم، أسماء ملفات فريدة (UUID)، والتخزين نفسه يرفض الأنواع غير المسموحة.
- **المفاتيح السرية** على الخادم فقط (`import "server-only"` يمنع وصولها للمتصفح أثناء البناء) و`npm run check-bundle` يتأكد بعد البناء.
- محاولات الدخول الخاطئة محدودة تلقائيًا من Supabase Auth.
- رسائل الخطأ للمستخدم مفهومة وبدون تفاصيل تقنية؛ التفاصيل تذهب لسجل الخادم (Vercel ← Logs) بدون أسرار.

## إضافة اللغة الإنجليزية لاحقًا

البنية جاهزة دون إعادة بناء:
1. **نصوص الواجهة:** انسخ `lib/i18n/ar.ts` إلى `en.ts` بنفس المفاتيح وترجمها، وأضفها في `lib/i18n/index.ts` مع `dir: "ltr"`.
2. **التوجيه:** انقل صفحات `app/(site)` إلى `app/[locale]/(site)` واقرأ اللغة من الرابط (`/en/...`).
3. **المحتوى:** أضف أعمدة إنجليزية (مثل `title_en`) في ملف migration جديد، وحقولًا مقابلة في لوحة التحكم. التصميم يستخدم خصائص منطقية (`start`/`end`) فيعمل في الاتجاهين.

## حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| «لم يتم ربط الموقع بـ Supabase بعد» | تأكد من `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` ثم أعد تشغيل `npm run dev` |
| «هذا الحساب لا يملك صلاحية إدارة الموقع» | نفّذ الخطوة 9 لهذا البريد |
| «استقبال الحجوزات غير مفعّل حاليًا» | أضف `SUPABASE_SECRET_KEY` في متغيرات البيئة (وفي Vercel) ثم أعد النشر |
| الصور لا تظهر بعد النشر | تأكد أن `NEXT_PUBLIC_SUPABASE_URL` مضاف في Vercel **قبل** البناء، وأن مساحة `media` عامة (Public) |
| «تعذر رفع الصورة» | تأكد من تنفيذ ملف التخزين، ومن حجم الصورة ونوعها، ومن أن جلستك لم تنتهِ |
| التعديلات لا تظهر | حدّث الصفحة؛ إن استمر، تأكد من نجاح الحفظ (رسالة «تم حفظ التعديلات») |
